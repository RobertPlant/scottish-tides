# Agent notes

Monorepo: `apps/mobile` (Expo universal app), `tools/` (station-fitting
helpers), `docs/`. Toolchain is pinned via `devenv.nix` at the repo root
(Node 24, Biome, Playwright browsers). Two linters, both gated in CI and not
overlapping: Biome from the root (`npm run check` — format, plus its recommended
rules and the React domain) and ESLint in the app (`npm run lint` — react-hooks
and import rules via eslint-config-expo). ESLint is sensitive to its dependency
versions; see the `//lint` note in `apps/mobile/package.json` before touching
eslint, typescript, or their resolvers.

## Stack

Expo SDK 57, Expo Router 57, React Native 0.86, react-native-web. Styling is
plain `StyleSheet` + a light/dark `Colors` palette in `constants/theme.ts`
(`ThemedText` / `useThemeColor` / `usePalette`). No backend, no auth, no network
calls at runtime — everything the app needs is bundled.

## The tide engine is the keystone

`apps/mobile/lib/tides/` is a TypeScript port of the harmonic predictor in
`~/org/scripts/tides.py` (vendored pytides2). It must stay numerically faithful
to the Python: **any change to the engine has to keep `npm run test:engine`
green**, which checks predictions against reference vectors generated from
`tides.py`. The strict gate is the hourly-height match (~5e-5 m actual); the
high/low-water *time* tolerance is amplitude-aware because near-amphidromic flat
ports (e.g. Port Ellen, ~0.5 m range) have ill-conditioned turning-point timing.
Regenerate the vectors with `tools/gen-reference.py` if you add a station.
`tools/verify-tidetimes.ts` checks every station against tidetimes.org.uk;
re-run it after refitting a station or recalibrating a shift.
`tools/calibrate-shift.ts` refits a secondary port's shift (Oban) from the same
source; `--write` updates its JSON.

Station data lives in `apps/mobile/assets/data/*.json` (one file per port:
constituents + datum + provenance) with a registry in
`apps/mobile/lib/stations.ts`. Some ports carry a `default_shift` to a secondary
port (e.g. Oban is derived from Tobermory by a constant offset). See
`docs/adding-a-station.md`.

## Android must stay Play-Services-free

The Android build targets F-Droid, whose inclusion policy bans Google Play
Services outright. **Never add a dependency that pulls in
`com.google.android.gms`** — that includes `expo-location`, which is why Android
uses the local `modules/platform-location` module (plain `LocationManager`),
`expo.autolinking.android.exclude` in `package.json`, and the
`lib/native-location.android.ts` platform split. iOS keeps `expo-location`.
`android/` is generated by `expo prebuild` and gitignored; build with
`npm run build:android` inside `devenv shell`. Details and the fdroiddata recipe:
`docs/android-build.md`, `fdroid/com.robertplant.scottishtides.yml`.

The release signing key is a repo secret used only by the Sign step of
`.github/workflows/release.yml`. Never route it through Gradle, Expo or EAS
or onto a command line — the repo and its Actions logs are public. Read
release logs with a targeted `grep`, never raw `tail`/`head`.

## RN-Web quirks

- **Don't pass an array `style` through `<Link asChild>`.** expo-router `<Link>`
  renders an `<a>` on web; with `asChild` the child's `style={[...]}` array
  reaches the `<a>` DOM node and React DOM throws *"Failed to set an indexed
  property [0] on CSSStyleDeclaration"* on mount. Use `useRouter().push()` on a
  plain `Pressable` instead (RNW flattens Pressable styles fine). NB with
  `unstable_settings.anchor`, the anchor tab mounts *under* pushed Stack screens,
  so a bad Home-screen Link crashes every route, not just `/`.

## Tests

Three layers, all in CI (`.github/workflows/test.yml`), alongside a `lint` job
that gates Biome (`biome ci`) and `tsc --noEmit`:

- **Unit** — `npm run test:unit` (node --test + tsx) runs **every** `*.test.ts`
  in the app (`"**/*.test.ts"`, node excludes node_modules): the pure helpers —
  datetime, tide-day, planner, streams, astronomy, geo — and the engine parity
  tests along with them. Keep the glob recursive; the old `lib/*.test.ts` meant
  a test file one directory deeper silently never ran.
- **Engine parity** — `npm run test:engine` (node --test + tsx) checks the TS
  engine against the committed pytides reference (`lib/tides/__fixtures__/`).
  A subset of `test:unit`, kept as the focused script for engine work.
- **e2e** — `npm run test:e2e` (Playwright) drives the **static export**, not
  the dev server: `playwright.config.ts` runs `expo export --platform web` and
  hosts `dist/` with `expo serve`. This matters — the web build ships as a
  static export, and its two worst bugs (build-time tide data baked into the
  HTML, every page titled with its URL) exist *only* in the exported artifact
  and sailed past a green run against `expo start --web`. Costs ~90 s of export
  per run. Specs in `e2e/`.

Running e2e on NixOS: `playwright.config.ts` auto-detects the devenv-provided
`PLAYWRIGHT_BROWSERS_PATH` and points Playwright straight at the nix
`chrome-headless-shell` via `executablePath` (the npm package's expected browser
build won't match the nixpkgs one otherwise). Run inside `devenv shell`. In CI
there's no such env var, so Playwright uses its own downloaded browser.

## More RN-Web quirks

- `Text` with `numberOfLines={N}` renders via `-webkit-box` line clamping;
  Playwright's `toBeVisible()` flags those as hidden — use `toBeAttached()`.
- expo-router on web keeps the previous tab screen mounted (and the
  `unstable_settings.anchor` tab stays mounted under pushed Stack screens);
  locators can resolve to two elements — scope to `:visible` / use `.first()`.
- Driving a controlled `<input type="date">` from a test: `fill()` doesn't fire
  React's `onChange`; set `.value` via the prototype setter and dispatch
  `input`+`change`. Also wait for dev-mode hydration first, or the synthetic
  event has no listener yet.

## Code style

From `~/projects/code-styles` (README + `typescript.md`), copied here because cloud sessions can't see
that path. Biome formats and checks from the root (`npm run check`, CI runs `biome ci apps/mobile tools`).

- 120 columns, single quotes, semicolons, trailing commas, `x => ...` with no brackets on one arg.
- Never nest ternaries, in JSX included. Use early returns or a small render helper. Biome's
  `noNestedTernary` enforces it.
- `async`/`await`, never `.then()`. Every promise is awaited, returned or `void`ed (`noFloatingPromises`).
- Braces on every `if`, `for` and `while`, one-liners included (`useBlockStatements`).
- `const`, not `let`, unless there's truly no other way. Pick a value with a small helper and early returns,
  not a default that gets reassigned.
- Never mutate what a function is given, and never change a value once it's made: no `.sort()`, `push` or
  assigning into something parsed, loaded or returned. Build the changed copy. The
  exception is a local the function is still building. `noParameterAssign` catches reassigning a parameter.
- Functional by preference: `map`/`filter`/`flatMap`, `Object.fromEntries` over loops that `push`.
- Hermes has no `toSorted` or `Map.groupBy`. In app code, `.sort()` the copy the function has just made (after a `map`
  or `[...STATIONS]`) and group with a loop filling a local Map, each with a one-line note:
  `// sort, not toSorted - Hermes doesn't have it`. `tools/` runs on Node, which has both.
- No index loops (`for (let i = 0; ...)`) in new code. Doing something n times is
  `for (const _ of Array.from({ length: n }))`, searching a range is `Array.from` then `find`. The engine's hot loops
  (`lib/tides/`) may stay, with a one-line note.
- Never call a function looked up by a key (`handlers[type]()`). Write the `if`s or a `switch` out, with a `never`
  check on a union.
- One `await` per line, never inside an expression. Work out the values together, a blank line, then the effects.
- A library over hand-rolled parsing, one already installed first. One helper per job: find the first copy before
  writing a second.
- Stored data is parsed into a type as it's read. A stored list drops only the records that fail their check,
  logging each, never the whole value.
- Errors keep their `cause`, caught errors are `unknown`, and nothing is dropped by an empty `catch {}` without a
  comment saying why it can't matter.
- A union of strings, not a bare `true`/`false` argument. An object with named fields past two return values.
- `lib/` is pure: data in, new data out. AsyncStorage, the router and the DOM belong in screens, components
  and hooks.
- Functions under ~50 lines (Biome warns). Screens and charts that are longer get split as they're touched.
- Name conditions before branching on them: `const isToday = ymd === todayYmd;` then `if (isToday) {`.
  Guard clauses up front, then the happy path, with a blank line before the final `return`.
- A function's name is a verb and its object (`getUrlDay`, `classifyDay`, `parseYmd`), not a noun
  (`tidalStats`, `dayEvents`). `get` for a value worked out from what's given, `find` for a search that can
  miss, `read`/`load` for storage, `parse` for unknown input, `build` for a new value, `list`/`count` for many,
  `render` for a helper returning JSX, `is`/`has` for a predicate. Rename old names when you touch them, not in a sweep.
- Names say what the thing is, closures included: `stations.map(station => ...)`, never `s`, `i` or `j`. A
  sort's comparator keeps `(a, b)`, an unused value is `_`, a caught error `err` and an event `event`.
- New helpers are arrow consts. Leave existing `function`s until you're changing them anyway.
- A file reads in one order: imports, then types, then constants in `SCREAMING_CASE`, then functions.
- No `as` in new code (`as const` is fine): narrow with a type predicate or a validator.
- Comments are rare one-line notes on why, not paragraphs. History goes in the commit or PR. When you change
  code, trim the comments on it to that too. No banner comments, ticket references or naming the tool that wrote the
  code. Docblocks only on exported functions, a title line and one sentence.
- No em-dashes anywhere, comments or copy. Use a hyphen, comma or full stop. UI copy changes go in their own PR,
  with any e2e assertion that quotes them.
- An engine change keeps `npm run test:engine` green (see above), and its test has to fail when the change is
  reverted.
